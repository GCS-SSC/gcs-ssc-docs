# Historical audit documentation impact

This register records documentation changes related to historical audit findings. It can be empty when the current source no longer contains those findings. Application audit logs are documented separately in [Audit and access logs](../admin/audit.md).

The documentation describes current behaviour and removes workarounds for fixed defects. This register omits sensitive security details, raw diagnostics, credentials and obsolete unsafe steps.

## Disposition rules

- Explain what the application does now and what that means for the officer.
- Remove old workarounds that depended on a defect; do not present them as supported steps.
- Check current code, database migrations, service configuration and relevant regression tests to confirm the behaviour. Record which tests you inspected and which you ran.
- Mark an item as fully verified only after the current rule is documented in English and French, or after recording evidence that it no longer applies.
